## 10. Recommendations / follow-up (non-blocking)

1. **Reconcile the brief's expected home size (409 B / 212 kB) with the actual (150 B / 190 kB).** The actual is leaner — a good outcome — but the brief was clearly written against a stale baseline. Either the brief is wrong or the production-size discussion in the D-0021/22/23 PR description should call out the size reduction explicitly so future audits don't flag it as a deviation.

2. **The `SectionDivider` is now the only hand-authored divider on the page (D-0018b removed `divider-flourish.svg`).** If the steward wants to reduce inline-SVG footprint further, the same 3-element pattern (path + dot + ring) could become a real shared component used by more than one section. No action needed for this audit.

3. **Bundle lockfile warning is pre-existing and benign.** Three lockfiles exist (`C:\Users\camer\package-lock.json`, `bun.lock`, `apps\web\bun.lock`). Next.js chose the npm one. If the steward wants a clean signal, removing the root `package-lock.json` or setting `outputFileTracingRoot` in `next.config.mjs` would silence the warning. Not introduced by D-0021/22/23.

4. **Curved-text rendering depends on Georgia being available as a fallback.** The passport-stamp's `<text>` declares `font-family="Georgia, 'Times New Roman', serif"`. On a device that lacks both Georgia and Times New Roman, the fallback is the system serif. The brand's primary font (Fraunces) is loaded via `next/font` for HTML but **not** for the inline SVG `<text>` (SVG inside a static file doesn't go through next/font's CSS variable pipeline). The fallback chain is reasonable; the rendered text is decorative so an inexact serif is acceptable.

5. **None of the new assets carry responsive sources.** `passport-stamp.svg` is a single 2,798-byte file rendered at 56–88px across breakpoints. This is fine — the SVG is small and scales infinitely. No action needed.
